## 2. Findings

### 2.1 [LOW] Stale "Master Candidates" state in `review-overview.json` (NEW)

The Review Overview sheet's first row is generated by a **hardcoded string** in
`build_catalogue_pages.py`:

```python
{
    "review_sheet": "Master Candidates",
    "record_count": len(manual_candidates),
    "purpose": "Evidence-backed official candidates awaiting an explicit master-promotion decision.",
    "source_file": str(MANUAL_CANDIDATES),
    "current_state": "reviewed_candidate / not_promoted",
},
```

But the actual review lane has moved on: `data/manual_master_candidates.csv`
has all 26 rows with `promotion_status=promoted` (see `promotion_notes`, which
cite owner approval and minted master IDs 353–357), and the committed
`docs/manual-candidates.json` sheet shows `promotion_status: {promoted}` with
`catalogue-meta.json` reporting `candidate_pending_promotion: 0`.

So the Review Overview tab now contradicts the Master Candidates tab it is
meant to describe: it says "not_promoted / awaiting a promotion decision" while
every candidate is promoted and none are pending.

**Root cause:** the label is a static literal, not derived from the actual
`promotion_status` column. The project's own documentation-currency tests
(`test_readme_current_state_matches_generated_data`,
`test_handoff_current_state_matches_generated_data`) only guard README and
`NEXT_AGENT_HANDOFF.md` numbers — **no test covers the `review-overview.json`
`current_state` strings**, so this drift is invisible to CI.

**Suggested fix (owner decision):** derive the label from the data, e.g. count
`promotion_status != "promoted"` and render the state accordingly
("all promoted" / "N promoted · M not_promoted"), or at minimum correct the
hardcoded string to "reviewed_candidate / all promoted". Optionally add a
doc-currency assertion for the review-overview row. This is a UI-guide label,
not data, so it does not affect any master/relationship counts.

## 5. Year-Month fix (2026-08-04, owner-directed)

**Problem.** The Year-Month column must show the **recording date**
(lectures/discussions) or **first release date** (books) — never the day a
product was **listed on the website**. Veritas lists a whole batch of classic
books with a `published_date` of `2014-03-30`, and
`build_research_master.backfill_months_from_official_source()` was using that
as the book `year`. That made *Power vs Force* = 2014 instead of **1995**, and
similarly misdated *The Eye of the I* (2001), *I: Reality and Subjectivity*
(2003), *Truth vs Falsehood* (2005), *Letting Go* (2012), *Healing and
Recovery* (2009), *Reality, Spirituality and Modern Man* (2008),
*Transcending the Levels of Consciousness* (2006), and *The Ego is Not the
Real You* (2021).

**Fix.** (a) `backfill_months_from_official_source()` now **skips
`item_type='book'` rows entirely** — a book's `year` is never derived from a
product-listing date. (b) First-publication years were set in the reviewed
inputs: `migration_review_ledger.csv` (23 book rows),
`data/manual_master_candidates.csv` (6 book rows), and
`data/edition_candidates.csv` (9 audiobook/carrier rows, set to their work's
first-publication year). (c) Catalogue codes are now lecture/discussion-only
(`CODE_ITEM_TYPES`) so books never receive a code even though they now carry
years — the code count stays **236**. A regression guard
(`test_books_use_first_publication_year_not_product_listing`) pins the classic
years and asserts books never get a catalogue code.

**Verification.** All five `--check` modes pass; 100/100 tests pass at 92%
coverage; `docs/master.json` shows Power vs Force = 1995 and The Ego is Not
the Real You = 2021; the only field changed in the three input CSVs is
`proposed_year` (23 + 6 + 9 rows). Docs updated (README, INSTRUCTIONS,
NEXT_AGENT_HANDOFF).

**Pipeline safe-trim (owner-requested).** `build_research_master.py` was
slimmed with a **behavior-preserving dedup**: added `read_csv` / `index_csv` /
`veritas_products_by_id` / `veritas_products_by_url` / `require_columns`
helpers and replaced the ~20 inline CSV-read blocks. No signatures or
semantics changed; output is byte-identical (`--check` green), 100/100 tests
pass, coverage 92% (module 615 → 580 statements). The residual weight is the
review-gated data model itself, not redundancy; a larger structural merge of
the manual + edition candidate lanes was offered but deferred as higher-risk.

## 9. Lecture recording-year correction (2026-08-04, owner-approved)

Investigation (`LECTURE_YEAR_INVESTIGATION.md`) found the 35 lectures showing
`year=2014` were carrying the Veritas **storefront-listing** date, not their
recording date. For the On-the-Road talks, Audible copyright lines (© = the
original recording year) are a reliable source, and they show **varying years
(©2003–2005)**, not a uniform 2003. On the owner's directive I corrected the
**8 verified talks** to their true recording years and **cleared their wrong
listing months** (year-only):

- ©2003: Compassion, God Is the Infinite Field, The Power of Devotion, You Are
  the Light of Consciousness
- ©2004: All Is Divinity, Spiritual Reality, Virtues
- ©2005: The Prevailing Silence

**Mechanism:** `backfill_months_from_official_source` now only fills a
lecture's month from the product date when the product's **year matches** the
record's year — so a 2014 listing month can no longer leak into a 2003–2005
record. Recording months known from titles (Become That Which You Are = June,
Love is a Way of Being = January, Unity Church March/June) were set in the
reviewed inputs. Extending the research to the whole batch: **13 On-the-Road
talks corrected** (2003–2005); the **18 Office Series talks keep 2014** (the
Office-Visit sets genuinely first-released 2014 — a correct first-release
date, not a wrong listing); **4 talks stay flagged** (Verification of
Spiritual Realities, God is Hidden, Peace is the Natural State, Don't Set
Sail) pending their © years. Catalogue codes **236 → 249**. Tests 102,
coverage 92%, all 5 checks green.
