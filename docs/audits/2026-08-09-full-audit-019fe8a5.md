## 0. Executive Summary

DocSheet is a **static GitHub Pages catalogue and review workspace** for the
Hawkins Archive — a curated collection of **362 master records** (lectures,
books, discussions, satsangs, etc.) by David R. Hawkins. The repository has a
two-lane architecture: a **raw spreadsheet lane** (CSV → `docs/data.json` via
`process_data.py`) and a **curated research catalogue lane** (ledger + overlays
→ `docs/master.json` via a multi-stage Python pipeline). The frontend is a
single-page Tabulator-powered table with dark mode, keyboard navigation,
mobile Browse cards, series/timeline discovery rails, and CSV export.

**Overall health: Solid with known debt.** The pipeline is deterministic,
well-tested (141 offline + 25 browser tests, 90% coverage), and the data
integrity is strong. The top concerns are: (1) **frontend monoliths** (2,769-line
`app.js`, 2,403-line `style.css`), (2) **root-level document sprawl** (20
`.md` files at root, 86 in `archive/`), (3) **owner UX scores remain 5/10**
(build accepted-but-not-confirmed), and (4) **CI/CD gating of Pages is
manual-pending** (documented in `.scoreboard/manual-workflow-edits.md`).

## 1. Architecture & Design (9/10)

### Strengths

- **Two-lane architecture** is clean and well-separated:
  - **Raw lane:** `hawkins archive clone - Sheet1.csv` (374 rows) → `process_data.py` → `docs/data.json` (7 columns after trimming 6 always-empty columns). Pass-through, no transformation.
  - **Curated lane:** `migration_review_ledger.csv` → `build_research_master.py` → `data/research_master_draft.csv` → `build_catalogue_pages.py` → `docs/master.json` + 13 other JSON views. Rich transformations, overlays, and reconciliation.
- **Pipeline modularized** into `pipeline/` package: `helpers.py` (shared I/O), `enrichments.py` (transformations), `validators.py` (structural checks), `relationships.py` (product derivation). All scripts have `--check` modes.
- **Deterministic & reproducible:** Every generator is idempotent, with tamper detection. Run-twice determinism is tested.
- **Delivery contract:** Content-versioned assets (`?v=<12-char-hash>`), `build-manifest.json` with full payload hashes, visible footer build ID, `FrontendDeliveryContractTests`.

### Issues

- **Frontend is not modularized.** `app.js` (2,769 lines) and `style.css` (2,403 lines) are monolithic single-file bundles. The scoreboard flags this as the top AI/user disagreement area (AI 8, user 6, effective 6).
- **No build step.** JavaScript is vanilla IIFE with no bundler, minifier, or tree-shaking. This is intentional for GitHub Pages simplicity, but means the 118KB `app.js` is served uncompressed.

## 2. Frontend — Web Design & UX

### Visual Design (8/10)

**Strengths:**
- **Clean neutral palette:** Light mode uses `#f9f9fb`/`#ffffff`/`#f4f4f5`/`#e4e4e7`. Dark mode uses `#0d0d0d`/`#161616`/`#222222`/`#282828`. No muddy slate-blue bleed.
- **Block colour system:** 11 distinct `data-block` colour tokens (lectures=emerald, discussion=rose, satsang=amber, on-the-road=teal, volume=indigo, office=sky, books=violet, transcription=fuchsia, media-misc=zinc, undecided=orange, fran-grace=crimson) with consistent 8.5% wash opacity.
- **Zebra contrast verified:** Light Δ≥10 luminance units, dark Δ≥6. Hover Δ≥7/8 from zebra. Enforced by 7 regression tests in `test_style_contrast.py`.
- **Typography:** Google Roboto (400/500/700) with proper font-display swap.
- **Custom scrollbars:** 16px wide, 8px border-radius, high-contrast neutral thumbs.
- **Loading skeleton:** Shimmer animation with `prefers-reduced-motion` respect.

**Issues:**
- **`unsafe-inline` in CSP `style-src`:** Required for dark-mode toggle (runtime class on `<html>`). Low severity — `script-src` stays hash-pinned and Tabulator is SRI-pinned.
- **CSS is 2,403 lines** with 14 `@media` query blocks, many targeting `(max-width: 720px)` — some could be consolidated.

### UX Features (8/10)

**Strengths:**
- **Jump-to dropdown** replaces cluttered horizontal tab strip.
- **Global live search** (`/` to focus, `?` for shortcuts) with `<mark>` highlighting.
- **Keyboard navigation:** j/k row traversal, y to copy filename, arrow keys for tab switching, roving tabindex, focus trap in modal.
- **Mobile Browse mode:** Card-based work browsing with Series shelf and Year rail discovery.
- **View settings:** Wrap cells, compact rows, summary cards, expand everything.
- **Dark mode:** localStorage persistence, respects OS preference, no flash of wrong theme (inline script before first paint).
- **CSV export** of active view.

**Issues (owner score 5/10):**
- **Exact dissatisfaction is undocumented.** The scoreboard notes `user_unhappy` for Pages presentation (5/10) and UX (5/10), with "Ask owner what falls short" as the next action.
- **25 Playwright browser specs exist** but owner visual acceptance is still required — artifact success ≠ owner acceptance.

## 4. Security & Privacy (8/10)

**Strengths:**
- **CSP is strict:** `default-src 'self'`, `object-src 'none'`, `script-src` hash-pinned for inline, CDN pinned via `cdn.jsdelivr.net` only. Tabulator loaded with SRI integrity hashes.
- **No `eval()`:** 0 uses in `app.js`. 5 `innerHTML` uses, all with static/template-literal HTML (no user-supplied data interpolated unsanitised — Tabulator handles cell content via `formatter` functions with `textContent`).
- **No third-party tracking:** No analytics, no ads, no external JS beyond Tabulator CDN.
- **`connect-src 'self'`:** No cross-origin XHR/fetch.
- **Form action self-only:** `form-action 'self'`.

**Minor concerns:**
- `style-src 'unsafe-inline'` — necessary for runtime dark-mode class toggle, low risk.
- `img-src data:` — allows inline data URIs (likely for SVG icons), low risk.
- Tabulator loaded from CDN — SRI protects integrity but introduces a supply-chain trust point.

## 5. Performance (8/10)

**Strengths:**
- **Virtual scrolling:** Tabulator's virtual DOM renders only visible rows. $O(1)$ `rowFormatter` (uses `row.getPrevRow()` instead of $O(N^2)$ traversal).
- **`renderHorizontal: "basic"`** — no rubberbanding on scroll.
- **`cache: "no-store"` on JSON fetches** — ensures fresh data after deploy.
- **Content-versioned assets** — CSS/JS get fresh cache bust on content change.
- **`prefers-reduced-motion` respected** — skeleton shimmer and card transitions disabled.

**Optimization opportunities:**
- `app.js` is 118KB uncompressed — could benefit from gzip/brotli at the CDN level (GitHub Pages supports gzip).
- `master.json` is 376KB — the largest JSON payload. Could be paginated or lazy-loaded.
- No service worker for offline support (acceptable for a GitHub Pages catalogue).
